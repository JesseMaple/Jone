## 三、环境启动方式（不污染系统）

### 1. 环境隔离说明

| 内容 | 位置 | 是否写入系统 |
|---|---|---|
| JDK 25 | `envs/jdk` | 否，仅 `$env:JAVA_HOME` 指向它 |
| Maven 3.9.16 | `envs/maven` | 否，仅加入当前会话 `$env:PATH` |
| 依赖仓库 | `envs/m2repo` | 否，`localRepository` 指向项目内 |
| Maven 配置 | `.mvn/settings.xml` | 否，经 `.mvn/maven.config` 生效 |
| 镜像 | 阿里云 `mirrorOf=central` | 只镜像中央仓库，JitPack 直连 |

**没有使用** `setx`、没有改注册表、没有写用户/系统环境变量，也没有向 `C:\Users\...\.m2` 写入任何依赖。

### 2. 启动步骤（PowerShell）

```powershell
Set-Location D:\DSHEAC_Exchanger\projs\Jone

# 第 1 步：仅对当前进程放开脚本执行限制（不写注册表，关闭终端即失效）
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

# 第 2 步：点源环境脚本（注意“点 + 空格”）
. .\env.ps1

# 第 3 步：启动应用
mvn javafx:run
```

`env.ps1` 只做三件事：设置会话级 `JAVA_HOME/PATH/MAVEN_OPTS`、把控制台切到 UTF-8（`chcp 65001`，仅当前窗口）、打印环境摘要。可以直接用 `mvn -v` 自查：

```
Apache Maven 3.9.16
Java version: 25.0.4.1, vendor: Eclipse Adoptium, runtime: ...\envs\jdk
```

### 3. 更省事的方式：双击启动

直接双击项目根目录的 **`启动Jone.cmd`** 即可。它内部调用 `launch-jone.ps1`（UTF-8 + BOM）完成同样的三步，全程不写系统环境变量。

> `.cmd` 只保留 ASCII 引导，是因为 `cmd.exe` 按系统代码页（GBK）解析批处理文件，UTF-8 中文会导致解析失败；所有中文提示集中在 ps1 里输出。

### ⚠️ 4. 必须知道的启动限制：不要从受限终端启动

本应用会直接使用你选择的真实路径写文件，**没有任何路径白名单或权限预判**。但 Windows 的「完整性级别」会影响子进程：

- 若从**普通 PowerShell / 资源管理器双击**启动（中完整性 Medium），可正常读写任意有权限的目录；
- 若从**受限终端 / 沙箱终端**启动（低完整性 Low），子进程会继承低完整性令牌，即使账户有完全控制权限，写入项目外目录也会被系统拒绝，并提示「无权限写入该目录（当前 Jone 运行在受限环境…）」。

判断方法：启动日志里出现 `【警告】当前 Jone 运行在受限环境` 即为受限启动，改用 `启动Jone.cmd` 或普通窗口即可。

### 5. 测试命令

```powershell
.\tests\run-tests.ps1                                   # 单元测试（45 项）
.\tests\run-ui-checks.ps1                               # 界面交互自检（7 项，会真实启动应用）
mvn test "-Djone.externalPath=D:\TempArea"              # 追加：真实写入任意外部目录
```

## 五、项目使用方法

### 1. 主界面

- **无边框窗口**：按住顶栏空白处拖动；双击顶栏切换最大化/还原；右上角三枚按钮分别是最小化、最大化、关闭。
- **侧边栏**：默认收起。鼠标移到窗口最左侧 12px 区域内停留 0.2 秒自动滑出；移开约 0.3 秒后自动收起。
  - 上方：主页、文件格式转换；下方：设置；中间一条水平实线把侧边栏分成上下两块。
  - 当前页面对应的按钮上下各有一条强调色短线（左右留白，不接触边框）。

### 2. 主页

- 中央偏上的大时钟，宽度占页面 **33%**、高度占 **30%**，随窗口缩放实时变化，每秒刷新。
- 时钟下方「文件格式转换」「设置」两个入口：**双击**进入对应页面。

### 3. 文件格式转换

1. 左侧选择**源格式**（默认 CSV），右侧选择**目标格式**（默认 JSON）。两侧不能相同，选择列表会自动屏蔽对方格式。
2. 点「选择文件」，文件对话框只显示当前源格式对应的后缀（CSV → `*.csv`；YAML → `*.yaml;*.yml`）。
3. 点「确认」（未选文件时为深灰不可用；选中后变为主题色）：
   - 先弹出无边框模态窗「是否覆盖原文件」：
     - **是**（绿底白字）：目标文件已存在时直接覆盖；
     - **否**（红底黑字）：目标已存在时自动加序号 `a_1.json`、`a_2.json`……；不存在时直接生成。
   - 转换结果显示在按钮下方：成功显示最终路径，失败显示中文原因（红色）。
4. 点「取消」清除已选文件。

### 4. 设置

- 路径：侧边栏「设置」→ 左侧分级菜单「系统设置 ▾」→「应用主题」。
- **预设颜色**：DeepSeek 蓝 `#4D6BFE`、樱花粉 `#FF9EB5`、紫罗兰 `#8B5CF6`、明黄 `#F5C518`、抹茶绿 `#8FBF5F`，每项前有色块。
- **自定义颜色**：R/G/B 三个数字框（0~255）+ 实时预览 + 「应用自定义颜色」。
- **跟随系统**：开启后，浅色系统用纯白背景 + 黑色文字与按钮；深色系统用极暗背景 + DeepSeek 蓝文字。系统主题变化时应用会自动重建界面。
- 主题影响范围：窗口三键标识色、侧边栏选中背景、整个应用背景色。

### 5. 配置文件 `config.json`

| 键 | 说明 | 默认值 |
|---|---|---|
| `theme.mode` | 主题模式：`preset` / `custom` | `preset` |
| `theme.presetId` | 预设主题标识 | `deepseekBlue` |
| `theme.customHex` | 自定义颜色 | `#4D6BFE` |
| `theme.followSystem` | 是否跟随系统 | `false` |
| `lastPage` | 上次停留页面：`home` / `converter` / `settings` | `home` |
| `window.width` / `window.height` | 窗口尺寸 | `1000` / `700` |
| `window.maximized` | 是否最大化 | `false` |
| `converter.sourceFormat` / `converter.targetFormat` | 转换页默认格式 | `CSV` / `JSON` |

所有修改都是「先写文件、再刷新界面」；文件被删除后下次启动会自动重建默认值。

### 6. 运维与调试开关

| 环境变量 | 作用 |
|---|---|
| `JONE_SNAPSHOT_DIR` | 启动 1.2 秒后自动截图到该目录并退出（自动化视觉验收） |

## 七、本轮缺陷修复记录（真实 UI 点击测试反馈）

| # | 现象 | 根因 | 修复 | 验证方式 |
|---|---|---|---|---|
| 1 | 工作区外路径转换提示「写入失败」，看不到具体原因 | `IOException` 被统一吞成一句泛化提示，权限原因未暴露，终端也没有堆栈 | `ConversionService` 按「无权限读取 / 无权限写入 / 目录不可创建 / 上层不是文件夹 / 文件被占用」分类翻译成中文，并对 IO 异常调用 `printStackTrace()` | 新增 5 项单测：绝对路径可转换、无权限写入提示、无权限读取提示、上层是文件、源文件不存在 |
| 2 | 转换后既不覆盖、也不生成 `_1.json` | ① `config.json` 里 `targetFormat` 已是 **YAML**，实际生成 `.yaml`，用户盯的是 `.json`；② 覆盖弹窗用阻塞式 `showAndWait()`，在动画/布局上下文调用会抛 `IllegalStateException`，异常把整条转换链吞掉且界面毫无反馈 | ① 弹窗改为非阻塞 `show()` + 回调，彻底消除该异常；② 弹窗内直接显示**确切目标路径**；③ 选文件后提示升级为「已选择 X → 将生成 Y」；④ `执行并显示` 增加兜底 `try/catch`，异常必定打堆栈并显示中文 | 自检脚本真实点击弹窗：默认生成 `学生表.json` → 再点「否」生成 `学生表_1.json` → 点「是」覆盖且不产生 `_2`；`格式切换并持久化` 另测格式与配置同步 |
| 3 | 右上角最小化/最大化/关闭三个按钮点了无反应 | `标题栏` 给按钮注册了 `MOUSE_PRESSED` 事件过滤器并 `consume()`，Button 永远无法进入按下状态，`onAction` 不会触发 | 删除该过滤器；防误触改为在拖动处理里判断「按下点是否落在按钮上（含子节点）」 | 自检模拟真实 `MOUSE_PRESSED` + `MOUSE_RELEASED`：动作触发=正常、最大化还原=正常 |
| 4 | 真实环境里转换 `D:\TempArea`、桌面等目录仍提示「无权限写入该目录」，但账户明明有完全控制权限 | 建设期为了修沙箱写权限，对**整个工作区树**执行过 `icacls /setintegritylevel Low /T`，把便携 JDK 的 `java.exe` 也打成了低完整性。Windows 创建进程时取「父进程令牌」与「可执行文件标签」中较低者，于是**项目 JDK 启动的所有 Java 进程都以 Low 运行**，写项目外目录被系统拒绝（代码里没有任何白名单） | 把 `envs/jdk`、`envs/maven` 两个目录树的完整性标签改回 **Medium**（517 + 110 个文件），其余工作区文件保持原样；新增 `运行环境诊断`，在启动日志与错误提示中明确区分「受限环境」与「真正无权限」；新增双击启动器，避免从受限终端启动 | 对照实验：同一 JDK 修正前进程为 Low、写 `D:\TempArea` 失败；修正后为 Medium、写入成功。正常权限下全量 45 项测试 0 跳过（含外部目录用例真实写入 `D:\TempArea`），受限环境下 44 通过 + 1 按设计跳过 |

## 八、已知说明与限制

1. **系统深色模式未实测**：本机为浅色主题，深色分支由单测覆盖（极暗背景、DeepSeek 蓝文字、选中背景压暗），切换系统主题后会自动生效。
2. **覆盖确认弹窗需人工点击**：自检已能自动点击「是/否」并验证转换结果，但弹窗的视觉呈现仍需人工确认一次。
3. **构建告警已清零**：SLF4J 缺失绑定通过引入 `slf4j-nop` 消除；JavaFX 上游 POM 的 6 条重复 profile 告警（Maven 3.9.7+ 的 [MNG-8147](https://issues.apache.org/jira/si/jira.issueviews:issue-html/MNG-8147/MNG-8147.html)）通过 `.mvn/maven.config` 对 `org.apache.maven.repository` 定向降级消除，构建失败时的 `[ERROR]` 仍然完整可见。
4. **受限终端启动**：从低完整性/沙箱终端启动时，应用只能写授权目录（启动日志会打印 `【警告】`）。这是 Windows 完整性级别机制，不是程序的路径限制；请用 `启动Jone.cmd` 或普通 PowerShell 窗口启动。
5. **`envs/download` 可删**：其中约 140MB 为安装包缓存，环境已解压完成，删除不影响运行。
